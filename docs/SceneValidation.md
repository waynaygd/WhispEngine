# Scene Validation

Open **View -> Scene Validation** and press **Validate Scene**. The panel checks the current Editor, Prefab Editor or Runtime World, with severity counts, filters, case-insensitive ASCII search, details and Select/Focus actions. Navigation checks the complete World/index/generation handle, including after deletion or slot reuse. Explicit navigation works with viewport Selection Lock.

Checks include registered component asset paths, file readability, material texture/shader dependencies, enabled scene environment/background resources, persistent scene IDs, serialized `$entity` references (including Lua fields), hierarchy validity, prefab source validity and local-to-scene member mappings. Source/member structural differences are warnings; ordinary component overrides are allowed. The project asset resolver and existing prefab/hierarchy/reference validation rules are reused.

Validation is a manual read-only snapshot: no resource requests, imports, GPU work, script execution, saves, scene edits or Undo records. Existing cached loader failures are warnings because they can predate a file repair. Not requested and Loading are not errors. Revalidate after editing files or the scene. Changing World/context disables old navigation; opening another scene clears the report.

Lua field type/range checks use only already cached metadata whose source text still matches the file. Without matching metadata, references are checked and an Info explains that field types are unverified. Validation does not obtain metadata by executing Lua, and does not check Lua syntax. Model/texture decoding and shader compilation are not performed; embedded textures check the container path and index syntax, not the presence of that index inside the model. File checks are cached per validation run; materials and prefabs have a 1 MiB inspection limit, scripts use LuaRuntime's 256 KiB limit, recursive reference inspection is bounded.

Targeted verification: build `WhispEngine`, `SceneValidationRegression` and `InteractiveRoomRegression`, then run those two regression tests. Fixtures use owned temporary files and preserve editor preferences. The scene-validation regression covers real Interactive Room and project paths, missing/unrequested/unsupported resources, material dependencies, broken/ambiguous entity references, prefab mapping, Lua metadata freshness, read-only guarantees, navigation, save/open, Prefab Editor and Runtime context. InteractiveRoomRegression covers placement, undo, movement, interaction and Clean Play Mode.
