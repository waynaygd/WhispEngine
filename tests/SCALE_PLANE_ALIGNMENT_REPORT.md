# Scale Gizmo Plane Handle Alignment

Ветка `scripting`. Commit/push/merge/reset не выполнялись.

## Причина

`DrawScalePlanes` строил собственную модель с `pose.scale={1,1,1}`. Она теряла знаки отрицательного Scale и всегда использовала положительные оси вращения. Между тем ImGuizmo нормализует **знаковые** столбцы исходной TRS-матрицы и в `ComputeTripodAxisAndVisibility` выбирает направление каждого маркера по сравнению проекций единичных положительного и отрицательного отрезков. Поэтому плоскости могли оказаться в противоположном секторе относительно нарисованных основных осей.

Вторая независимая ошибка — размер. Старый код использовал:

```text
length = depth * tan(verticalFov / 2) * 0.24
```

ImGuizmo `ComputeContext` получает `mScreenFactor` из проекции camera-right с нормализацией aspect ratio. Для текущей перспективной камеры при размере ImGuizmo 0.1 это:

```text
length = depth * tan(verticalFov / 2) * 0.1 * max(1, viewportWidth / viewportHeight)
```

Нефоршортенированная ось занимает `0.05 * max(viewportWidth, viewportHeight)` в логических координатах UI. Старый коэффициент совпадал бы с этой моделью только при одном частном aspect ratio. Ни порядок матриц, ни viewport origin не были первопричиной.

Ссылки на исследованную vendored реализацию: `external/imguizmo/src/ImGuizmo.cpp`, функции `ComputeContext`, `GetSegmentLengthClipSpace`, `ComputeTripodAxisAndVisibility`, `DrawScaleGizmo`, `GetScaleType`. Файл не изменён.

## Исправление

- `DrawScalePlanes` получает ту же исходную матрицу, которая передаётся в ImGuizmo::Manipulate, включая знаки Scale.
- `ScalePlaneGeometry.h` нормализует знаковые направления, повторяет правило выбора направления ImGuizmo и использует его модель экранной длины.
- `ScaleGizmoClipSize` явно передаётся и в ImGuizmo, и в собственную геометрию. Размер не зависит от абсолютных величин non-uniform Scale.
- Четыре вершины каждой плоскости проецируются из соответствующих локальных направлений в координаты того же Viewport.
- Внешняя граница ограничена 85% длины осей. Внутренняя граница отступает настолько, чтобы освободить штатную область выбора оси ImGuizmo (12 px + 1 px запаса) и центральный квадрат ±10 px (окружность радиуса 15 px включает его углы). Порог площади 25 × DPI² квадратных логических пикселей исключает слишком мелкие ручки. Это ограничения доступной области, а не смещения, подобранные для конкретной камеры.
- Проверяются все три осевых сегмента. Вырожденные, слишком узкие, перекрывающие оси или выходящие за Viewport плоскости не рисуются и не выбираются.
- Размеры и координаты — логические координаты ImGui. Framebuffer scale не применяется повторно. DPI учитывается в минимальной площади захвата; текущая DPI-семантика drag сохранена.

## Hit-testing и взаимодействие

Рисование, hover и capture используют один `ScalePlanePolygon` с четырьмя вершинами. При совпадении нескольких областей подсвечивается и захватывается только одна. Tooltip соответствует XY/XZ/YZ.

Во время hover/capture плоскости ImGuizmo продолжает рисовать основные оси, но на время единственного вызова Manipulate его штатная проверка `IsHoveringWindow` получает отдельное NoInputs-окно `gizmo`, созданное BeginFrame, вместо Viewport. Сразу после вызова исходный `ImGuiContext::HoveredWindow` восстанавливается. Координаты и события мыши не меняются. Это исключает одновременный axis capture/hover и не меняет обработку настоящего осевого drag. Раньше при plane capture код возвращался до Manipulate, скрывая основные оси. В текущем публичном API ImGuizmo нет отдельного вызова «отрисовать без обработки ввода», поэтому используется этот короткий scope существующего ImGui context.

`ScalePlane` и существующие транзакции сохранены: меняются только два компонента, знак сохраняется, Snap работает, release создаёт одну Undo-запись, Undo/Redo восстанавливают значения, Escape отменяет drag без новой записи. Shear не добавлялся.

## Проверки

Новый `ScalePlaneGizmoRegression` использует независимый oracle: вызывает настоящий ImGuizmo, разбирает индексированный ImDrawList на связные примитивы и извлекает центры реально нарисованных концевых окружностей осей. Затем сравнивает их с рассчитанными осями и проверяет принадлежность плоскостей соответствующим экранным секторам. Для oracle отключён ввод и выделены цвета отдельных осей; геометрия рисуется неизменённой vendored реализацией.

Матрица проверок: горизонтальный/вертикальный Viewport, FOV 0.5/1.0/1.8 rad, расстояния 2/20/2000, DPI 1/2, фронтальная и повёрнутая камера, Rotation 0/45°/90° по каждой оси, единичный и отрицательный non-uniform Scale.

Нативный DX12-тест дополнительно:

- запускает Application и создаёт сцену с Cube;
- сверяет вершины hit polygon с фактическим ImDrawList редактора с допуском на AA/обводку;
- кликает и перетаскивает XY/XZ/YZ через синтетические события UI;
- проверяет отсутствие ImGuizmo axis capture, знаки, неизменность третьего компонента, Snap, одну Undo-запись, Undo/Redo, release и Escape;
- сохраняет кадры настоящего редактора и проверяет DX12 validation.

Старый Editor Level Workflow больше не вычисляет координаты клика по прежней ошибочной формуле. Проверка drag сохранена, а независимость геометрического oracle обеспечена отдельным тестом.

Результаты:

- Полная Release-сборка: **PASS**, `out/scale-final-build.log`.
- Финальный полный CTest: **37/37 PASS**, 202.86 секунды, `out/scale-final-ctest.log`.
- Независимый oracle: **1080 комбинаций, 1917 видимых плоскостей**, без расхождений с концевыми окружностями ImGuizmo (допуск 0.15 логического пикселя).
- Новый нативный regression и существующий Editor Level Workflow DX12: **PASS**, включая захват/drag всех трёх плоскостей, Snap, Undo/Redo и Escape.
- Финальная отдельная нативная проверка с исходным пользовательским layout: **PASS**, `out/scale-native-final.log`. Кадры «после» обновлены этим запуском и просмотрены.
- DX12 validation errors: **0**. `git diff --check`: **PASS**.

В первом полном прогоне обнаружено конкурирующее осевое захватывание в диагностическом layout. Оно исправлено блокировкой штатного window-hover gate ImGuizmo во время собственного plane drag. После исправления выполнен указанный выше полный повторный прогон; тесты не ослаблены и не исключены.

## Ограничения

Плоскость может скрываться при взгляде почти ребром, совпадении осей на экране, маленьком Viewport, недостаточной области между осевыми handles или близости к границе Viewport. Скрытая область не перехватывает мышь. Это намеренное безопасное поведение; осевые и uniform handles остаются доступны.

Поддерживается существующая перспективная камера и TRS без shear. Изменение системного DPI Windows в живой desktop-сессии вручную не проверялось; проверены логические координаты/DPI-пороги и различные размеры Viewport в oracle. Геометрия согласована с текущей vendored версией ImGuizmo; её будущие изменения размеров/axis flip должны сопровождаться запуском независимого теста.
