# Character Movement и PlayerStart

Ветка: `scripting`. Сцены не изменены. Коммиты и отправка в remote не выполнялись.

## 1. Причина дополнительного падения

Игрок был обычным вращающимся динамическим Box с half extents `(0.30, 0.85, 0.30)` и friction `0.8`. Контроллер задавал горизонтальную скорость, но не ограничивал угловую степень свободы. Контактные импульсы трения вращали тело; оно ложилось на бок. Центр опускался примерно на `0.85 - 0.30 = 0.55` метра. Sleep скрывал проблему до начала ходьбы, когда тело просыпалось.

Воспроизведение до исправления, при указанной в задании высоте пола:

```text
rest=-0.496443 minimum moving=-1.04698 dip=0.550537 pitch=1.5708
```

`tests/CharacterMovementRegression.cpp::Reproduce` оставляет обычное незаблокированное тело для сравнения. Исправленный игрок проверяется отдельно при 60 и 120 физических шагах в секунду: dip `0`, pitch/roll `0`.

В `engine/ecs/systems/PhysicsSystem.cpp` функции `ApplyImpulse` и позиционная коррекция используют `ApplyInverseInertiaWorld`. Новый `RigidbodyComponent::lockRotation` возвращает нулевой inverse inertia и очищает начальную angular velocity. Поэтому вращение блокируется также внутри solver, а не сбрасывается после уже произошедшего наклона. Физика остальных тел сохраняется.

Дополнительные ошибки: камера читала Transform перед физическим шагом без RenderInterpolation; eyeHeight прибавлялся к центру тела; PlayerStart использовался как центр тела, а не точка ног. Эти ошибки устранены отдельно.

## 2. Движение и физика

- Ввод собирается раз в кадр; нормализованное направление применяется перед каждым fixed physics tick. Диагональ не ускоряет игрока, несколько тиков за кадр не теряют команду движения.
- Только Rigidbody интегрирует позицию. Y не фиксируется вручную. После ухода с края пола персонаж падает.
- Jump — запрос по фронту нажатия, потребляемый один раз физическим тиком. Он сохраняется до ближайшего тика, но не повторяется при удержании Space.
- Grounded подтверждают контакты с направленной вверх нормалью и допустимой вертикальной скоростью. Вертикальная стена не считается землёй.
- При освобождении мыши направление и запрос прыжка очищаются; следующий физический тик обнуляет горизонтальную команду. Существующие Tab/Escape и захват курсора сохранены.
- Камера получает позицию после физики из того же RenderInterpolation, который используется рендерингом тела. eyeHeight измеряется от ног.
- Скорость хранится в CharacterMovement. При загрузке старого `Player.moveSpeed` значение переносится в CharacterMovement, если там нет явно сохранённой скорости. Явное новое значение имеет приоритет.
- PlayerStart исключён из PhysicsSystem, даже если в старой сцене на маркер вручную добавлены Rigidbody/Collider.

Размеры Collider уже выражены в мировых единицах. Игрок не имеет MeshRenderer, его autoFitFromMesh выключен, offset равен нулю, runtime scale равен единице. Масштабирование маркера не удваивает размеры Collider. Для поверхностей существующий asset auto-fit продолжает учитывать границы mesh и Transform.scale; эти правила не менялись. Плоский mesh сам по себе имеет нулевую толщину; верх вручную настроенного Box может отличаться от видимой поверхности на его halfExtent.y. Это не объясняет воспроизведённое падение на 0.55 м.

## 3. Создание и Play/Stop

`Viewport → Create → Player → Player Start` создаёт `PlayerStart` с Tag, Transform и включённым PlayerStartComponent; сразу выделяет его. Создание — одна Undo-транзакция, Undo возвращает предыдущее выделение, Redo восстанавливает маркер. В Play создание запрещено.

В Hierarchy до изменения не было меню создания, поэтому отдельный дублирующий интерфейс там не добавлен. Маркер обозначен типом `[PlayerStart]`.

Transform.position теперь означает положение ног. Y rotation задаёт направление, X rotation — начальный наклон камеры в пределах ±89°. Физический Box остаётся вертикальным; roll и scale маркера не меняют тело. Inspector объясняет эту семантику.

Runtime World получает одного игрока из первого активного маркера с Transform. Центр поднимается на halfExtent.y. Все runtime-маркеры, в том числе выключенные и старые физические маркеры, удаляются. Editor World не изменяется. Нет активного маркера — нет автоматически созданного игрока, Play продолжает работать.

## 4. Gizmo

В Scene View рисуется силуэт человека постоянного экранного размера с тёмной обводкой и светлым цветом. Щелчок по нему выбирает маркер до mesh picking. Направление показано стрелкой из точки глаз.

Для выбранного маркера отображаются 12 рёбер Box, отметка ног и жёлтая точка `Eyes`. Ширина/высота/глубина — `0.60 × 1.70 × 0.60`. Положение центра, размеры, yaw и высота глаз берутся из общих функций/значений `engine/ecs/PlayerSpawn.h` и PlayerComponent, используемых настоящим спавном. Gizmo обновляется при изменении Transform. Game View и Play его скрывают.

Это только ImGui overlay: на маркер не добавляются Collider/Rigidbody и графические ресурсы.

## 7. Ограничения

- Это динамический Box controller. Автоматический подъём по ступеням, capsule sweep, moving-platform attachment и полноценный slope controller не добавлялись.
- Спавн не ищет автоматически свободную точку. Дизайнер должен разместить видимый preview вне стен/пола; при исходном пересечении работает обычный contact solver.
- Иконка — overlay поверх сцены, без проверки окклюзии геометрией. Размер силуэта постоянный, размеры физического preview — мировые.
- Точная пользовательская сохранённая сцена не была передана; причина воспроизведена на отдельной сцене с теми же параметрами пола и игрока.
- Ручная проверка физических клавиш WASD/Tab/Escape в видимом окне не выполнялась. Автоматические проверки используют настоящий physics solver, приложение/DX12 и синтетические события UI; это не заменяет такую ручную проверку.
